# 暖石墨桌面技术验证

日期：2026-10-22。状态：只读链路已接通，候选路线，尚未替换原客户端或完成 M1。

## 路线与判断

用户认可交互原型后，本轮验证 .NET/WPF 最小桌面宿主 + WebView2 本地界面。WPF 负责窗口、文件选择器与生命周期，已确认的 React/CSS 界面负责显示，Core/Worker 继续负责归档读取。窗口使用本地构建资源，不依赖 Vite 服务。

选择这一候选是为了复用已确认的界面和 C# 归档逻辑，先验证真实数据、进程边界及部署。它证明界面与现有引擎能够衔接，并不证明资源占用最优。原生控件深度定制路线尚未进行同场景性能对比；最终框架继续保留评估空间。

## 构建与运行

```powershell
./scripts/Build-Desktop.ps1 -Run
./scripts/Build-Desktop.ps1 -Run -Archive 'D:\Archives\example.zip'
# 已恢复依赖且原型预览正在运行时：
./scripts/Build-Desktop.ps1 -SkipRestore -Run
```

生成 `.artifacts/desktop-validation/Release/AileArc.Desktop.Validation.exe`，宿主和 Worker 均携带 .NET 运行时。还需要系统已有 Microsoft Edge WebView2 Runtime；脚本不自动安装运行时、不修改信任设置、不登记文件关联。前端开发预览的依赖在被 Vite 占用时不能直接清空重装，需先关闭这个项目的预览，或者使用 `-SkipRestore`。

可直接在程序中点击“打开”选择文件。原客户端与安装器仍独立保留；该验证程序不是正式发布版本。

## 已接通的行为

- 读取真实归档元数据；目录导航、全包名称搜索、名称/大小排序。
- 区分同名 Entry、大小写不同目录；使用会话内独立 ID，不把路径当作唯一键。
- 每页最多 200 项，行数据 JSON 上限 512 KiB；侧栏最多展示 100 个根目录，更多目录仍可从主列表访问。分页后选择限定在当前页。
- 密码输入、错误后重试、取消请求；ZIP 的自动/UTF-8/GBK/Shift-JIS 重新扫描入口。
- 只读模式不提供模拟解压、新建或外部打开；这些控件标明尚未接入并禁用。
- 当前元数据模型不含修改时间，显示“—”，不伪造日期。界面仍以简体中文验证，正式迁移时需接回双语资源。

## 边界

- 本地页面固定为 `https://ailearc.local/index.html`，只映射程序的 Web 目录，不映射用户文件目录。
- 页面采用构建期 CSP；宿主检查消息来源、消息类型、版本、ID、长度、搜索/分页/编码范围；拒绝未知字段和任意路径/执行命令。
- 原生文件选择器决定可打开的文件。浏览器只发送选择文件的请求，不传入任意磁盘路径。
- 使用 JSON 序列化传输数据，文件名交给 React 作为文本显示；不拼接脚本。外部导航、子框架导航、新窗口、下载和权限请求均阻止，不暴露通用宿主对象。
- 归档解析仍在 Worker。WebView2 的渲染隔离不等于整个应用的权限沙箱，也不保证其运行时自身没有更新等网络活动。
- 构建索引前保守限制隐式目录展开的估算量：50 万节点、64 Mi 字符累计前缀预算。原 Worker 的原始条目/元数据限制仍生效。
- 大列表取消延迟、冷启动、辅助功能、完整中文/英文、Shell 与安装迁移、真实提取/创建/工作副本尚未完成新界面验收。

### 资源观测（非性能基准）

ZIP 小样本分页、搜索及 UI 自动化检查期间，宿主与其 WebView2 共 7 个进程：工作集合计约 591.6 MiB，私有提交合计约 366.9 MiB。工作集可能重复计算共享页；私有提交也不等同于物理内存驻留。本次是运行后的单次观测，包含辅助功能检查影响，没有做冷启动或多轮统计。

自包含目录约 271 MiB（未压缩、含宿主/Worker 的运行时副本，不含系统 WebView2 Runtime）。这说明接入路线可行，但还不能据此承诺轻量。下一轮应测量启动与取消延迟、私有内存，并与原生定制界面做同样样本的比较，再确定最终宿主。
