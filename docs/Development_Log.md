- 新增构建/控件自检 CI 步骤，测量脚本支持 WPF 和独立输出目录，数据与截图保存到忽略目录。详见 WPF_UI_Validation.md。推荐纯 WPF 为下一阶段主候选，等待设计/技术决策，不替换现有客户端、不创建 Release。

## 2026-10-22：Native SDK 暖石墨原型与 WebView2 对比

- 按用户要求新增独立 Native SDK 0.11.0 TypeScript/Native markup 原型，保留原客户端及现有 Core/Worker。真实只读适配器复用 ArchivePresentation 的 200 项分页；1,000/100,000 项生成渲染样本单独标识。
- 原生构建确认无 Web 层，实机报告 Direct2D。接通中文字体、搜索、复选框、多选计数、详情、目录/分页入口；实际 100,000 项 ZIP 可浏览并搜索末项。
- 完成实际中文输入法候选提交；发现候选框位置偏离搜索框，以及 Windows UI Automation 仅识别外层窗格，作为未通过完整验收的限制保留。
- 修复字节数组插值导致的后端 URL 错误并增加回归；复测发现 SDK 复选框保留旧值，原型通过只重建批量变更的复选框子节点修正，全选/清除与计数即时一致。
- 工具链遇到 npm 包遗漏构建 fixture、Windows 主题路径比较及 CRLF 裁剪问题，固定完整源码版本并保存两处局部补丁；固定高度虚拟列表使用受支持的常量估计器路径。未手改生成 ABI。

- 顺序运行两种宿主、两种真实 ZIP、各两次采样。私有提交：1,000 项 Native 335.9–337.5 MiB / WebView2 346.7–349.4 MiB；100,000 项 Native 375.8–376.5 MiB / WebView2 402.8–408.4 MiB。工作集合计差异更大，但不能当作实际物理内存节省。
- 新增复现脚本、固定工具链、字体许可和原型 CI 构建。完整边界/数据见 Native_UI_Validation.md；没有发布 Release、标签、官网，也没有切换正式 UI 技术。
