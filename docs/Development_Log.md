## 2026-11-06：合并并发打开与系统选择器结果

- 显式多窗口同时打开相同归档版本、条目 ID 和包内路径时，共用一个执行确认、准备及启动请求。重复请求转向正在处理的窗口；拒绝或结束后释放记录，后续主动打开仍可复用已编辑的副本。

## 2026-11-06：在私有工作副本中保留可用的解码内容

- 单条目外部打开专用通道可保留非加密普通文件的非空输出，仅接受引擎明确报告的数据错误、CRC 错误或提前结束。候选字节先留在登记过的暂存文件中，Core 收到完整协议并确认 Worker 正常退出后才向私有副本发布。普通解压的失败计数、重试和目标覆盖语义沿用严格校验。
- 未校验副本使用 v2 清单记录错误、解码字节数与可知的原始大小；普通副本使用 v1。旧版开发包实读同一目录，只列出健康的 v1 样本。新客户端对清单的写入和读取使用一致的 128 KiB 预算，编码超限时在解码前停止。
- 普通解压、私有副本、清单及另存暂存文件在写入前核对登记身份，持有文件句柄写入和改名。下载来源标记在文件名受保护期间写入。真实损坏 ZIP 验证另存字节及 ZoneId、原包和既有解压目标的内容；故障子进程覆盖零输出、错误密码、方法不支持、超长输出、虚报成功、异常退出、追加错误帧与取消。

## 2026-11-06：缩短正式客户端从启动到首个数据页的时间

- 新增乱序及重复 ID、超长中文名称、末项无序、返回数组隔离和加密新窗口密码提示回归。最终 173 项 .NET 测试、中英文 WPF 自检、原生 Shell 接口及开发包 Worker 的 10 项冒烟测试通过。同机交替测量中，十万项平铺 ZIP 的首行进入绘制从 1,621 ms 降至 1,152 ms；详细时间、内存及取消时的工作量见[完整对照](WPF_Client_Performance.md)。

## 2026-11-06：查看和清理中断任务

## 2026-11-06：核对恢复记录与父目录

- 用异常退出子进程复现旧版误判：将暂存文件所在目录改名，再在原位置创建空目录，旧版会报文件缺失，清理时会遗忘仍在旧目录中的残留。v2 登记时保存父目录 ID，目录不符则保留记录。v1 记录仍可按匹配的文件身份清理；没有父目录身份且文件已消失时保守保留。
- 清理用户确认的项目时核对登记记录的内容、文件身份与快照，以及暂存文件的实际版本。删除只作用于已验证且持有的句柄。登记 JSON 的首次创建、更新和失败清理也改用持有的暂存句柄。登记内容超出读取预算时在创建载荷前拒绝。
