# AileArc 架构决策记录

## ADR-016：正式采用纯 WPF 自定义界面（2026-10-23）

状态：用户已确认，取代 ADR-001 的 WinUI 3 前提以及 ADR-013/014/015 的待选状态。

- 正式客户端采用 .NET 10 / WPF / XAML 自定义控件模板，保留暖石墨设计。Core、Worker、7-Zip 引擎与现有安全边界继续复用。
- 新客户端在 src/AileArc.Client 渐进接入；验证项目保留为历史基线，不作为正式运行依赖。正式窗口不含生成压力样本和实验框架选择入口。
- 先迁移真实浏览、密码、编码、排序和语言资源；随后迁移解压/外部打开/工作副本、创建/恢复，再整合多窗口激活、安装与 Shell。每批更新迁移矩阵并验证。
- WinUI 旧客户端在功能对齐和安装验收前作为回归参照保留；不提前用未对齐的 WPF 包替换已有安装、关联或 Shell 入口。
- UI 不加载 7z.dll；耗时扫描/索引/查询在后台执行。语言复用 Core 的 zh-CN/en-US 资源及设置，切换后重启生效。
- 迁移依据与验收见 WPF_Client_Migration.md；M1 的容量与安全要求不变，不创建正式 Release。

## ADR-015：纯 WPF 暖石墨独立验证（2026-10-23）

状态：用户授权对照验证，正式技术栈尚未锁定。

- 新增独立 WPF 控件/模板界面，直接复用现有 Core/Worker 与 ArchivePresentation；无 WebView2 或 HTTP 中间适配器。其他客户端保留。
- 使用同一批 1,000/100,000 项 ZIP、相同 200 项真实分页，重新测量三种宿主。生成大列表单独验证虚拟化，不将不同模型的数据占用混作公平比较。
- 保留 TextBox 的 IME、DataGrid 的选择与 UI Automation，再定制视觉。原生控件默认键位不自动等同于文件管理器行为，实测差异作为产品化待办记录。
- 自检使用实际 WPF 控件，结合实机候选框、滚动、多选和系统语义观察；资源数据区分私有提交与工作集，不能将热启动样本当作冷启动指标。
- 验证结果见 WPF_UI_Validation.md；本轮不迁移写入能力或发布正式版本。

## ADR-014：Native SDK 独立验证与同样本对照（2026-10-22）

状态：用户授权验证，尚未锁定正式客户端技术。

- Native SDK 指 Vercel Labs 的工具包，不是 Windows SDK。新增独立 TypeScript/Native markup 原型；不采用嵌入 React/WebView 的兼容路径。
- 保留现有 Core/Worker，以只读本地适配器接入同一 ArchivePresentation。原型与 WPF/WebView2 使用相同真实 ZIP、索引和 200 项分页；十万项纯界面样本另行标记，不能混作扫描性能。
- 本地适配器只接受启动时指定的归档；随机回环端口、每次启动令牌、只读查询、参数和输出大小限制。HTTP 只是验证通信方案，不预先锁定正式 IPC。
- 重点验收中文文本/实际 IME、虚拟列表、多选和整个进程树资源占用。Node 状态测试不等于原生窗口验证；UI 内部自动化树也不等于 Windows 辅助功能支持。
- 依赖固定 Native SDK 0.11.0 / Zig 0.16.0 / scriptc 0.3.0；完整源码加局部 Windows 构建补丁用于复现。已发现的上游测试失败必须保留在验证记录中。
- 暖石墨设计保持不变；现有两条客户端路径保留，M1 功能开发不因本轮原型被宣称完成。

## ADR-013：真实数据桌面验证（2026-10-22）

状态：候选路线验证，尚不替换原客户端。

- 用户认可交互原型并授权继续推进，进入技术验证及真实功能接入阶段。

- 本轮接通真实浏览、搜索、分页、密码及编码入口。写入、外部打开、双语、窗口管理和安装迁移还未接入新界面。

## ADR-001：首版范围与架构边界（2026-09-15）

状态：已接受。

UI 使用 WinUI 3；Core 管理浏览模型、任务与规则；Worker 执行归档解析；Engine 封装完整 7-Zip 能力。第一条可运行链路就使用独立 Worker。工程按实际需要建立，暂不创建插件 SDK 等空壳。

M1 是数月迭代的日常可用里程碑，不等于第一个原型。内置预览推迟，Windows 默认应用负责打开工作副本。首版包含基础 ZIP/7Z 创建，已有包编辑后置。Shell 早期验证、M1 后半段落地。

## ADR-004：内部原型引擎与 IPC（2026-09-15）

状态：已实现并通过基础验证。

- .NET SDK 10.0.100，Windows App SDK 1.8.260804001，Windows 11 x64；NuGet 锁文件纳入源码。
- 官方完整 7-Zip 26.03 的 7z.dll，仅在 Worker 中通过 C# COM ABI 调用。尚未引入第二个引擎。
- IPC 使用专属子进程重定向 stdin/stdout 管道，长度前缀 JSON 帧；不是公共命名管道，不需要对外暴露服务。
- 一次扫描或解压一个 Worker。Job Object 限制进程数、768 MiB 提交内存，并在父进程终止时杀掉 Worker；不宣称完整权限沙箱。
- UI/Core 不加载 7z.dll。扫描中保留原始条目 ID，Core 单独组织目录导航。
- 当前限额：250,000 Entry、32 Mi 路径字符、单帧 1 MiB、单次提取 4 GiB；读取/解码无协议活动超时 2 分钟。
- .resw 以明确资源名内嵌 Core 程序集，由 LanguageService 读取 XML 资源；不依赖系统语言自动匹配。后续如迁移 MRTCore，保持资源键及行为兼容。

## ADR-005：首轮解压边界（2026-09-15）

状态：基础实现；后续继续安全验收。

- Worker 仅输出 Entry 元数据和 32 KiB 数据片段，不接收目标路径，也不在目标文件系统落盘。
- Core 在开始输出前验证全部选中条目的路径、链接标志、预估容量。
- 每个目标的祖先目录以不跟随重解析点的句柄逐层验证并持有，拒绝目标目录联接点；首轮仅支持本地盘。
- 文件先写随机同目录 `.partial`，收到成功校验结果并确认长度后提交；取消/校验失败清理本任务临时文件，不覆盖已有内容。
- Smart Extract 通过 CreateDirectory 原子预留新目录；普通解压有重名询问及应用到后续冲突。
- 传播 Internet/Restricted ZoneId，不复制下载来源 URL。目标不能保存必要来源标记时不提交文件。
- 旧版 RAR 的 POSIX 类型可能位于 Windows 属性高 16 位，必须结合 0x8000 标记识别链接；不能仅检查 kpidSymLink。
- 未完成：强制退出后的残留回收、全部崩溃窗口验证、完整归档版本身份校验、分卷与网络目标、权限沙箱和性能基准。

## 待验证的技术选择

- 分卷、多种密码/格式边界与更大样本；当前已验证普通 ZIP、7Z、RAR 与加密 7Z。
- 干净机器的部署及未来 sparse package 的现代 Shell 集成；本机无打包构建已运行。
- Worker 权限限制、协议模糊测试及完整故障恢复。
- 引擎枚举、索引、UI 及 IPC 的内存占用；不提前承诺百万条目性能。

参考：[Windows 本地化](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/mrtcore/localize-strings)、[现代右键菜单](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/integrate-packaged-app-with-file-explorer)、[7-Zip 许可](https://www.7-zip.org/license.txt)。

## ADR-006：所选条目与源文件身份（2026-09-15）

状态：已实现。

- 文件按 Entry ID 选择，目录按大小写敏感的完整路径边界扩展，避免 Project 匹配到 Project2。
- IPC 协议版本 3。Worker 从正在持有的归档文件句柄读取卷/文件索引、长度和修改时间；Core 在写入前比较浏览时的身份快照。

## ADR-007：默认应用打开与副本保护（2026-09-15）

状态：基础实现。

- 通过 ShellExecute 打开单个已校验工作副本；未关联时使用 SHOpenWithDialog，不改变用户默认关联。
- 可执行/脚本/快捷方式扩展名先确认。普通文档直接打开，不提供内置预览。
- 副本单独存储，先持久化准备记录，再提取内容、计算 SHA-256 基线、持久化完成记录；完成前不能启动外部应用。
- 每个副本目录显式限制为当前用户访问。同一会话重复打开已准备的条目复用已有副本，不覆盖外部修改。
- 10 秒后台检查最近打开副本；管理界面选中副本和正常关闭时重新检查。共享冲突/丢失时保留而不清理。
- 所有工作副本都跨退出保留，避免外部编辑器在 AileArc 退出后才保存导致丢失。暂不做自动清理；恢复管理入口读取准备记录并标识未完成项。
- 另存使用同目录临时文件和替换提交，不修改原压缩包；禁止另存覆盖原包或副本存储目录。取消/失败清理自有临时文件。
- 下载 ZoneId 记录在副本元数据，编辑器替换保存后不因 ADS 丢失而失去原始来源标记。
- 当前外部打开/副本导出限制 256 MiB；单副本恢复记录限制 128 KiB，恢复扫描最多 2000 个副本目录。
- 后续：副本清理 UI、完整多窗口协调、基于变更通知的检测调度、外部修改显式回写。

## ADR-009：文件名编码与归档创建（2026-09-16）

状态：基础实现。

- ZIP 手动编码采用 7-Zip ISetProperties 的 cp，限制自动/65001/936/932；读取、提取、工作副本使用相同会话选择。其他格式暂保持自动。
- 压缩创建通过 Worker 的 IOutArchive/UpdateItems，限定 ZIP Deflate 与 7Z LZMA2；密码走私有 IPC，不进入命令行或临时清单。
- Core 枚举源清单、拒绝同名根项/重解析点/目标落入源目录，按目录边界去重重叠选择，保留源目录句柄以防替换。
- Worker 不跟随源文件重解析点，核对长度/修改时间并保持只读源句柄到写入完成；不对主动伪造文件时间作完整内容认证承诺。
- 输出是 Core 在目标目录创建的随机空暂存文件。原生编码结束后重新打开，并以引擎 test mode 校验全部条目；成功才提交/替换目标。
- 默认不覆盖；UI 明确确认后允许覆盖。取消、源文件变化或校验失败时移除本任务暂存文件，保留原目标和源文件。
- 预设级别 1/5/9，最多 2 线程；7Z 字典 4/16/32 MiB，ZIP 密码 AES-256。文件名加密要求 7Z 且有密码。
- 首期上限 10,000 条目、4 GiB 输入；不支持分卷、已有包更新、源文件自动删除。目标剩余空间的预估提示后续完善。

## ADR-010：多窗口及数据清理（2026-10-03）

状态：已实现基础行为，M1 尚未完成。

- 每个用户、会话、安装路径使用一个独占命名管道服务端；转交请求只包含规范化路径，不传入可执行命令。管道限制当前用户，限制请求大小并对最终回执确认后断开。
- 主进程按路径和文件身份复用窗口，窗口共享工作副本服务与会话语言。统一重启前逐窗口检查任务与副本，替代进程等待旧进程退出后恢复压缩包路径。
- 工作副本清理为显式操作，要求外部编辑器关闭。删除前重新读取记录、锁住文件并核对基线哈希，遇到修改、占用、链接或额外文件拒绝清理；目录只尝试非递归删除。
- 解压/创建/副本导出/副本元数据暂存文件具备持久记录和独占租约。正常完成/取消清理记录；异常退出后租约由系统释放，恢复界面提供显式清理。
- 删除前核对记录格式、文件名、卷标识和文件 ID，通过已验证的文件句柄标记删除，避免校验后按路径重新定位。
- 父目录缺失或卷身份变化不会等同于暂存文件已提交；此时保留记录。已知父目录和卷内仅文件缺失时可移除过期记录。
- 未登记文件、记录写入自身的残留、未完成身份登记、无法安全确认的目标均不自动删除。断点续作、批量清理与全盘搜索不在此阶段范围内。

## ADR-011：开发部署与 Shell 命令（2026-10-03）

状态：开发部署与命令接口已实现，现代 Explorer 注册待签名环境验收。

- UI/Worker 分别发布自包含 win-x64，补充 WinUI PRI/XBF 资源的发布复制；增加运行时目标的 NuGet 锁定信息。
- Shell 为无 CLR 的原生 C++ IExplorerCommand DLL，菜单查询只处理有限选择元数据，Invoke 将显式动作与路径传给现有单实例入口。归档引擎仍只在 Worker。
- 语言标题由官方 .resw 生成编译表；当前会话语言在启动时写入专用 ShellLanguage 值，不随系统语言自动改变。
- 开发安装限定当前用户，以独立版本目录、文件哈希清单、专属注册值和收据管理升级/卸载；从不接管 UserChoice。只移除未变化的自有文件，不触碰用户工作副本。
- 现代菜单选择 sparse package 以保留自定义安装路径。未签名包实测被 Windows 的可执行激活规则拒绝；提供已有证书签名入口，不自动修改系统信任或开发者模式。
- 普通开发安装支持升级回滚；已注册现代包的开发安装暂要求卸载后重新安装，完整安装中断恢复与图形安装器后续推进。
