# AileArc 首个里程碑实施规范

状态：用户已确认。日期：2026-09-15。

本规范将产品蓝图收敛为首个里程碑 M1 的实施依据。M1 允许数月迭代，不等于首次代码提交或内部原型。与旧蓝图不一致时，本规范优先。功能完成情况以开发历程为准，不能把计划标记为已经实现。

## 1. 平台与产品目标

- Windows 11 x64；不支持 32 位系统。Windows 10 后续支持，ARM64 未来评估。
- 原生 C# / .NET / WinUI 3 桌面应用；高风险解析通过 Worker 执行。
- 完成“打开 → 找到 → 交给默认应用查看 → 解压所需内容”的日常流程。
- 基础功能应尽量在 M1 完成，不以差异化为由推迟常用操作。
- 百万 Entry、100 GB 是理想容量规范；M1 先保证响应、取消、资源有界和正常样本可用。
- GitHub 开源并记录开发历程；暂不急于官网、正式 Release 或自动更新体系。

## 2. 范围与开发顺序

### M1-A：技术链路（内部原型）

- UI → Core → IPC → Worker → Engine → Entry 列表。
- 打开、目录浏览、搜索、排序、取消、基本错误分类。
- 从首条链路引入 Worker，不先在 UI 中解析再迁移。
- 批量传输元数据，Entry ID 独立于路径；合成缺失目录，保留重复 Entry。
- 任务状态模型、资源预算、密码交互边界从基础阶段设计。

### M1-B：日常操作

- ZIP/7Z/RAR 浏览、导航、名称搜索、排序、基础属性。
- 文件名编码选择：Auto、UTF-8、GBK、Shift-JIS 等；显式切换后重新读取显示。
- 双击包内普通文件：提取工作副本，交给 Windows 默认关联应用。
- Extract Here、Extract To、Extract Selected、Smart Extract、Extract and Open。
- 密码、进度、取消、冲突处理、CRC/完整性结果、部分失败报告。
- ZIP/7Z 新建压缩包：格式、预设、密码、输出位置。
- 工作副本变化检测、另存为与关闭保护；不自动回写压缩包。

### M1-C：Windows 工作流

- 少量现代右键命令：智能解压、解压到、新建压缩包等。
- 文件关联与 Open With，尊重用户选择。
- 最小开发安装、升级验证与卸载支持，自定义安装位置。
- 多窗口、重复打开激活已有窗口；同一包的身份需考虑规范路径和文件标识。

### 后续功能

内置文本/图片/PDF/音视频预览、已有包内添加/删除/重命名、外部编辑自动回写、标签页、缩略图网格、虚拟文件拖出、插件、挂载、密码保险库、复杂分卷创建、官网与正式发布体系。

## 3. 打开与浏览规则

| 操作 | 默认行为 |
|---|---|
| 打开第二个压缩包 | 新窗口；重复打开同一个包激活已有窗口 |
| 双击目录 | 进入目录 |
| 双击普通文件 | 准备工作副本，再调用 Windows 默认关联应用 |
| 双击嵌套压缩包 | 提取后交给关联应用；关联 AileArc 时新窗口打开，不做内部多层挂载 |
| 无默认关联 | 使用系统“打开方式”界面 |
| 连续打开同一条目 | 合并未完成准备请求，避免重复提取与重复启动 |
| 打开大文件 | 显示“正在准备打开”，可取消；取消后不得再启动应用 |
| 打开时校验失败 | 说明原因，用户主动决定是否打开可用内容 |
| 可执行内容 | EXE、脚本、快捷方式等明确确认后运行；普通文档直接打开 |
| 文件依赖旁边内容 | 默认仅提取所选文件，提供“解压所在文件夹”；不暗中解压整个包 |
| 搜索 | 默认整个包，不区分大小写的名称包含匹配；可切到当前目录范围 |
| 搜索结果 | 展示内部路径；双击目录进入并退出搜索，后退恢复搜索及选中状态 |
| 默认排序 | 目录在前、名称升序；其他列支持显式排序 |

工作副本保存不会修改压缩包。打开时给出轻量提示；提供工作副本位置入口。检测修改后标记状态并允许另存为。已修改工作副本不能按普通缓存自动删除。外部编辑回写后续独立实现。

## 4. Smart Extract

基于最外层实际内容决定是否套目录；隐式目录也参与判断。规则不猜测 README、说明文件或隐藏文件的重要性，不擅自改变内容结构。

| 根内容 | 结果 |
|---|---|
| 只有一个目录 | 直接提取该目录，不额外套压缩包同名目录 |
| 只有一个普通文件 | 直接提取该文件 |
| 多个文件或目录 | 新建压缩包同名目录，容纳全部内容 |
| 一个目录加说明文件 | 属于多个根项目，创建压缩包同名目录 |
| 空压缩包 | 提示为空，不创建目录 |
| 最终名称已存在 | 自动使用新名称，不默认合并或覆盖 |

目录重名例：Project → Project (2)。文件重名例：report.pdf → report (2).pdf。名称分配在实际写入时必须处理竞争，不能仅凭预检查覆盖文件。复合扩展名如 .tar.gz 生成容器名称时按已识别格式处理。

Extract Here 严格按包内结构解压到当前位置，不暗中套目录；用户指定目标的普通解压允许目录合并，由冲突策略控制文件覆盖。包内重复文件名和 Windows 大小写碰撞同样进入冲突处理。

## 5. 解压与任务语义

- 普通解压冲突默认询问：替换、跳过、自动重命名；可应用到后续冲突。
- 取消后保留已经完成的文件，仅清理本任务创建的未完成文件；不得删除任务之前已有的目标文件。
- 部分失败显示“部分完成”，列出失败项；不能报告全成功。
- 普通解压完成默认不弹出目录；提供“解压并打开”和可记忆设置。
- 有任务时关闭窗口：等待或取消并退出；首版不引入隐藏常驻。
- 密码仅在当前压缩包会话内复用，关闭清除，不持久保存、不写日志。
- 首版恢复承诺：状态可解释、残留可清理、任务可重试；不承诺压缩断点续作。
- 精确进度未知时使用不确定进度；Reading/Extracting/Writing/Verifying 分阶段，不能伪造 ETA。

## 6. 语言与区域

- 官方语言 zh-CN、en-US；首次启动固定简体中文，不自动跟随系统语言。
- 设置入口“语言 / Language”；选项“简体中文”“English (United States)”。
- 首版采用独立 .resw 资源编译随程序发布，源码位于 Strings/<language>/Resources.resw；不分散硬编码界面文本。
- 保存语言选择后，当前界面保持原语言，重启整个应用后生效。
- 提供“立即重启”“稍后”；有活动任务时不直接重启或自动取消，外部修改副本按关闭规则保护。
- 多窗口统一使用本次进程会话语言，重启后统一切换。
- 缺失翻译回退简体中文；构建检查资源键和占位符一致。
- Windows 自有对话框可保持系统语言，不重新实现系统界面以强求一致。
- 日期、时间、数字格式沿用 Windows 区域设置；语言切换不修改文件名、路径、文件内容或编码选择。
- 中文/英文均检查布局、键盘访问、提示文本，不拼接零散翻译片段。
- 外置语言包加载后续扩展。

## 7. 安全与数据模型基线

- UI 不加载归档解析引擎；Worker 崩溃不得拖垮 UI。进程隔离不等于权限沙箱。
- 引擎能力、格式能力和当前归档状态分别判断；不支持的操作在执行前解释。
- ArchiveSession/EntryID 标识条目，路径不是唯一键；保留原始路径、显示路径与提取映射的区别。
- 提取必须校验路径、设备名、ADS、绝对路径、链接/重解析点和实际目标写入边界。
- 在真正写入前实现资源预算、实际输出限制、私有临时目录、异常清理与来源标记策略。
- 诊断日志不含密码/文件内容；Crash Dump 不能当成天然脱敏数据。
- 日后更新已有归档时，同卷临时构建、校验、原包变更检测与提交恢复需独立设计；分卷不套用单文件原子替换承诺。

## 8. 验收

- 标准 ZIP/7Z/RAR 样本可打开；错误、加密、损坏与不支持格式可解释。
- 中文、英文、重复路径、隐式目录和大小写冲突有测试样本。
- 浏览与搜索在非 UI 线程进行重操作；快速切包、搜索或取消时旧结果不覆盖新状态。
- Worker 故障/超时/取消释放资源，下一任务可继续。
- Smart Extract 规则和冲突/取消/部分失败具备自动测试。
- 所有提取/外部打开能力在启用前通过相关安全测试，不以引擎第三方成熟为由省略。
- 测量普通样本首屏/索引时间、峰值总内存和取消延迟，记录硬件与样本条件；大样本作为逐步扩展能力。
- 在干净 Windows 11 x64 环境验证构建运行、两种语言、安装卸载和 Shell 体验。
- 首次代码链路未完成上述全部功能时，明确标为内部原型，不能宣称 M1 完成。
